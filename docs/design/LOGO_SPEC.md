# 헤더 로고 반영 스펙

## 문제
`public/logo.png`는 화이트(투명 배경) 브러시 스크립트 로고다. 기존 다크 테마
(검정 AppBar)에서는 잘 보였지만, 리디자인된 라이트 배경(`color-bg #FAFAFA`)에서는
거의 보이지 않는다. 픽셀 확인 결과 로고는 RGBA `(255,255,255,alpha)` — 흰색 잉크,
투명 배경 — 이라 흰 배경 위에서 사실상 사라진다.

## 해결
- `public/logo-black.png` 신규 추가 — 원본 로고의 알파(브러시 질감·안티앨리어싱)는
  그대로 유지하고 RGB만 `#111113`(`color-text-primary` 토큰과 동일)로 반전.
- 트림: 원본 512×256 캔버스의 좌우/상하 여백을 제거하고 여유 패딩 14px만 남겨
  343×176(가로:세로 ≈ **1.95:1**)로 크롭. 헤더에서 불필요한 투명 여백 없이
  높이 기준으로 바로 배치 가능.
- 기존 `public/logo.png`(흰색)는 그대로 유지 — `layout.tsx`의 파비콘(`icon: "/logo.png"`)
  등 다른 용도에서 계속 쓰일 수 있으므로 삭제하지 않음. 헤더 전용으로 새 파일만 추가.

## 적용 위치
`src/components/logo.tsx` — 현재 텍스트 워드마크(`j1n<span>.</span>uk`)를
`logo-black.png` 이미지로 교체. 이 컴포넌트는 `page.tsx`, `not-found.tsx`,
`login/page.tsx`, `expired/page.tsx`, `g/[slug]/page.tsx` 전체 화면에서
공유되므로 한 곳만 바꾸면 전체 반영됨 (스펙 문서 [SCREEN_SPECS.md](./SCREEN_SPECS.md)의
6화면 전부 대상).

## 크기 가이드 (검증 완료 — 브라우저 렌더 스크린샷 기준)

| 브레이크포인트 | 높이 | 비고 |
|---|---|---|
| 모바일 (`<640px`) | **32px** (최소 28px) | 28px도 가독 가능하나 브러시 획이 얇아 32px을 기본값으로 권장 |
| 데스크톱 (`≥1024px`) | **40px** (최소 36px) | |

- 너비는 자동(`width: auto`), 높이 고정 — 비율 1.95:1 유지 (`next/image`라면 `width={343} height={176}` 원본 지정 + CSS로 `height` 재정의, 또는 `fill` 없이 고정 h만 지정)
- 컨테이너: 기존 `Logo` 컴포넌트의 `mb-8`(하단 마진), `text-center` 정렬 그대로 유지 — 이미지도 헤더 중앙 정렬
- `alt="j1n.uk"` (텍스트 워드마크와 동일 의미 전달, 접근성)
- 링크 동작(`Link href="/"`)은 기존과 동일하게 이미지를 감싸도록 유지

## 검증 결과
- 라이트 배경(`#FAFAFA`) 위 대비: 다크 텍스트(#111113) vs 배경 대비비 15:1 이상, 육안 확인 스크린샷으로 가독성 확보 확인
- 모바일 28/32px, 데스크톱 36/40px 4단계 모두 브라우저 스무스 스케일링(LANCZOS 급)로 렌더 시 뭉개짐 없이 선명 — 32px/40px을 기본 권장값으로 확정
- `next/image`의 기본 최적화 스케일링을 쓰면 실제 프로덕션에서도 동일하거나 더 나은 품질 예상 (원본 343×176이 목표 렌더 크기의 4배 이상 해상도라 레티나 대응 별도 @2x 자산 불필요)
